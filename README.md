# CRISP Simulator Project
## _Critical Slice Prefetcher_
This is a lightweight implementation of *[CRISP](https://research.google/pubs/crisp-critical-slice-prefetching/)*(Critically-Aware Instruction Scheduling) to ChampSim's out-of-order core.
The goal is to identify long-latency loads at run time, track the instructions that feed them, and give those instructions higher priority when scheduling.

## Overview of Implementation
- **Track dependencies**:
As instructions enter the ROB, we record simple producer-consumer relationships so we can later walk backward through an instruction's slice.
- **Detect critical loads**:
When a load retires, we measure its actual memory latency. If it crosses a dynamic threshold (which adjusts based on the running average latency), we treat that load as "critical".
- **Build a backward slice**:
For each critical load we walk back through its small dependency chain and mark the involved instructions as `critical`. Their PCs are also remembered so future dynamic instances can be tagged immediately.
- **Prioritize in the scheduler**:
During execution, ready critical instructions are issued before non-critical ones. The ROB head is still guaranteed forward progress, so the pipeline stays safe.
- **Lightweight by design**:
The slice depth, dependency tracking, and thresholds are all inherently small so the mechanism stays simple and avoids heavy bookkeeping.

## Setup Steps

### Champsim Setup
- Install ```vcpkg``` submodule
```sh 
git submodule update --init
vcpkg/bootstrap-vcpkg.sh
vcpkg/vcpkg install 
```
- Compile
```sh 
./config.sh my_config.sh
make
```

## Result Summary

We evaluated CRISP on five different traces.
All runs used the **25M-instruction** configurations in:
- [Baseline](ChampSim/results/baseline_final/)
- [CRISP](ChampSim/results/crisp/)

The table below shows the performance impact of CRISP on a small set of traces:

| Benchmark      | Baseline IPC | CRISP IPC | % Increase |
| -------------- | ------------ | --------- | ---------- |
| BFS            | 0.1617       | 0.1636    | 1.18%      |
| Exchange       | 1.312        | 1.325     | 0.99%      |
| LimitOrderBook | 1.184        | 1.243     | 4.98%      |
| ReverseLL      | 0.6817       | 0.6912    | 1.39%      |
| SSSP           | 0.2207       | 0.2211    | 0.18%      |

**Notes on the traces:**

* **BFS:** Standard BFS trace.
* **Exchange:** SPEC CPU 2017 *exchange* trace.
* **LimitOrderBook:** Trace generated from the open-source LOB implementation using an AVL-tree book ([https://github.com/brprojects/Limit-Order-Book](https://github.com/brprojects/Limit-Order-Book)).
* **ReverseLL:** Trace generated by us from a large linked-list reversal.
* **SSSP:** GAP benchmark trace.
